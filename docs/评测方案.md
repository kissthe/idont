# 评测方案

版本 v0.1 · 2026-10-08 · 配套 `任务定义与标签判定.md`、`docs/锚点字段说明书.md`

本文说明拿到评测题（`data/questions/**/<name>.json`，eval.json 格式）之后，怎么让模型作答、怎么打分、怎么判断这批题是否可用。

---

## 1. 评测要回答的问题

| # | 问题 | 用什么回答 |
|---|---|---|
| Q1 | 模型能否判断“这个反应是否需要个人历史来解释” | T1 必要性判断的 macro-F1 |
| Q2 | 需要历史时，能否找对线索、定位到证据 | T2 线索准确率、T3 证据 P/R/F1、联合正确率 |
| Q3 | 模型会不会“见到历史里提过的东西就硬套” | 误归因率（按 P / I 子类拆开） |
| Q4 | 模型是真的用了历史，还是只看当前输入就猜出来 | 三种输入条件的差值、成对一致率 |
| Q5 | 题目本身是否可用 | 只给 X 的天花板检查、人类基线、标注一致性 |

---

## 2. 输入：题目文件与旁注

每个题目文件配一个同名的 `.meta.json`，按 `sample_id` 对应。评测脚本**必须**读取其中的 `history_filter`：

| 字段 | 作用 |
|---|---|
| `history_filter.until_session` | 历史只取到这个 session 为止（含）；`null` 表示整段对话 |
| `history_filter.exclude_sessions` | 从历史中删掉这些 session（“I-无历史关联”题，共 12 题） |
| `conv_id` | 到 `locomo10.json` 里取哪段对话 |
| `context_turns` | X 前面对方说的话；渲染时放在目标轮之前 |
| `x_date` | X 的日期，放在当前情境的标题里 |
| `sample_type`、`i_subtype`、`option_roles`、`supporting_turn_ids` | 只用于打分和分析，**不给模型看** |

**删除 session 后要重新编号。** 否则历史里会出现 `session_3` 直接跳到 `session_5` 的缺口，相当于提示模型“这里删过东西”。重新编号只影响“I-无历史关联”题，这类题的 gold 证据为空，不影响打分。

---

## 3. 三种输入条件

按任务定义，每个模型、每道题都跑三遍：

| 条件 | 历史部分给什么 | 用途 |
|---|---|---|
| `x_only` | 不给历史 | 检查标签能否只凭 X 猜出来。分数高说明题目泄漏，要回头改数据 |
| `full_history` | 按 `history_filter` 截取的完整历史 | **主结果** |
| `evidence_only` | 只给证据所在的 session | 上界：去掉检索难度后，模型能否完成判断 |

`evidence_only` 的取法：
- H 题：`gold.evidence_session_ids`。
- 同一锚点派生的非 H 题（`P_same_cue`、`I_near_miss`、`I_no_reaction`）：取同一 `family_id` 下 H 题的证据 session。这些 session 对它们来说是“诱饵历史”，正好考模型会不会因为历史就在眼前而误判成 H。
- `I_no_history`：证据 session 已被删除，此条件下历史为空，等同于 `x_only`，不单独统计。
- `P_unrelated`：没有对应锚点，不跑此条件。

## 4. 提示词与输出格式

### 4.1 渲染

```
[任务说明]

## Conversation history
### session_1 (4:06 pm on 23 January, 2023)
[D1:1] Jolene: ...
[D1:2] Deborah: ... [shares an image: <caption>]
...

## Current situation (<x_date>)
Jolene: <context turn>               ← 如果有
Deborah: <text>   <- target turn

## Candidate cues
- cue_deborah_small_amulet: the small amulet
- ...
- none: 无可支持的历史线索
```

- 轮次 ID 直接用 LoCoMo 原始写法（`D4:28`），和 gold 的格式一致，模型可以照抄。
- 图片用 LoCoMo 自带的 `blip_caption` 渲染成文字；描述可能有错，这是已知局限（见第 10 节）。
- 候选项的顺序就是题目文件里的顺序（生成时已经打乱）。另外按第 6 节做一次换序重跑。

### 4.2 任务说明（英文，与数据语言一致）

任务说明包括：三个标签的定义（取自任务定义）、什么算“反应”、证据只能取 u 自己说的轮次、证据必须早于当前情境，以及输出格式。完整文本以 `tools/build_questions.py` 里的 `INSTRUCTIONS` 为底稿，再补上“什么算反应”这一条。

### 4.3 输出格式

```json
{"label": "history_supported", "cue_id": "cue_deborah_small_amulet",
 "evidence_turn_ids": ["D4:36"], "current_emotion": "comfort"}
```

- `label` ∈ {history_supported, present_cause_sufficient, insufficient_evidence}
- `cue_id`：候选项之一；label 不是 history_supported 时填 `none`
- `evidence_turn_ids`：label 不是 history_supported 时为 `[]`
- `current_emotion` ∈ {sadness, fear, anxiety, anger, nostalgia, comfort, joy, guilt, none_observed}

**是否允许先推理再作答：** 主结果要求直接输出 JSON。另跑一组“先写简短理由、最后输出 JSON”的变体作为补充，比较推理对误归因率的影响。

### 4.4 解析规则

1. 从回复里取最后一个合法的 JSON 对象；取不到就重试一次（相同输入），仍失败记为 `parse_fail`。
2. `parse_fail` 在所有指标里都按答错计，并单独报告失败率。
3. `cue_id` 不在候选项中，按 `none` 计。
4. 证据 ID 去掉空格、统一成 `D<数字>:<数字>`；不符合格式的丢弃。
5. 模型输出 label 不是 H、却又给了线索或证据：按 label 为准，线索和证据不参与打分（即视为 none 和空）。

## 5. 指标

记 gold 标签为 y，预测为 ŷ。H 指 history_supported，P 指 present_cause_sufficient，I 指 insufficient_evidence。

| 指标 | 计算范围 | 定义 |
|---|---|---|
| **T1 macro-F1**（主指标） | 全部题 | H、P、I 三类 F1 的平均；同时报告每类 P/R/F1、准确率和混淆矩阵 |
| **T2 线索准确率** | gold 为 H | 预测 cue_id 等于 gold_cue_id 的比例（预测 label 不是 H 的算错） |
| **T3 证据召回 / 精确率 / F1** | gold 为 H | 逐题计算后取平均。召回 = 命中的 gold 证据 / gold 证据数；精确率分两种：严格（只认 `evidence_turn_ids`）和宽松（命中 `supporting_turn_ids` 不算误报） |
| **T3 session 命中率** | gold 为 H | 预测证据里至少有一轮落在 gold 证据 session 中的比例 |
| **联合正确率** | gold 为 H | T1 对、T2 对、且证据召回 ≥ 0.5 |
| **误归因率**（关键诊断） | gold 为 P 或 I | 被预测成 H 的比例；按 P_same_cue / P_unrelated / I_near_miss / I_no_history / I_no_reaction 分别报告 |
| **成对一致率** | H 与对应的 I_no_history | 两道题都答对的比例。X 完全相同，只有历史不同，所以只有真正用了历史才能都答对 |
| **情绪准确率**（辅助） | 有反应的题 | 预测情绪等于 gold 的比例；不进入主排名 |

**条件差值：** Δ = full_history − x_only（T1 macro-F1），以及 evidence_only − full_history（检索差距）。

**统计：** 题量小（目前 63 题），所有指标都报告 1000 次 bootstrap 的 95% 置信区间。两个模型的差异用配对 bootstrap 或 McNemar 检验，不只看点估计。

## 6. 鲁棒性检查

| 检查 | 做法 | 看什么 |
|---|---|---|
| 选项位置偏差 | 每题再用一种不同的选项顺序跑一遍（none 保持最后） | 两次结果的一致率；T2 是否随位置变化 |
| 解码随机性 | 主结果用 temperature 0；对 1 个模型用 temperature 0.7 跑 3 次 | 指标的波动范围 |
| 历史长度 | 按历史 token 数分桶 | 长历史下 T1、T3 是否下降 |
| 锚点距离 | 按“证据 session 与 X 相隔几个 session”分桶 | 远距离证据是否更难 |

## 7. 被评测模型

- **闭源前沿模型 2–3 个**，来自不同厂商。
- **开源模型 2–3 个**，覆盖不同参数规模（例如一大一小），用于观察规模效应。
- 所有模型的上下文窗口需不少于 32k token（目前历史最长约 1.8 万 token，加上任务说明仍有余量）。
- **检索基线 1 个：** 用 X 的文本作为查询，从历史里按 BM25 或向量相似度取前 k 轮（k = 10、20），只把这些轮次作为历史给模型。它代表“记忆系统”式的做法，用来回答“整段读入 vs 先检索再判断”哪个更好。

具体模型名称和版本在实验开始时确定，并写进运行配置里。

---

## 8. 数据可用性检查

评测结果同时用于检验数据本身：

1. **只给 X 的天花板。** x_only 条件下 T1 macro-F1 应接近随机水平（三分类约 0.33）。超过约 0.5 就说明题目泄漏：逐题列出所有模型在 x_only 下都答对的 H 题，回头检查 X 是否把原因说出来了（golden_triples 里 A05、A07、A08 的审查提示已经预判了这个风险）。
2. **evidence_only 应不低于 full_history。** 如果给了证据反而判不出 H，说明证据本身不足以支撑 H，要回头修 gold。
3. **人类基线。** 抽约 30 题（覆盖各题型），两名未参与出题的标注者在 full_history 条件下独立作答：
   - 人类 T1 准确率是参考上限，期望 ≥ 0.8；
   - 两人的 Cohen's κ 期望 ≥ 0.6；
   - 人类也答错或两人分歧的题，回到标签判定流程裁决，必要时修改或删除。
4. **难度分层。** 所有模型都答对的题记为“简单”，所有模型都答错且人类答对的题记为“难”，用于后续扩充数据时调整配比。

## 9. 执行步骤与产物

```
results/<run_id>/
├── config.json              模型、条件、解码参数、提示词版本、题目文件及其 git 提交号
├── raw/<model>/<condition>.jsonl   每题的完整输入哈希、原始回复、解析结果、token 用量
├── scores.json              所有指标（含置信区间）
└── report.md                主表 + 分组表 + 错误样例
```

| 步骤 | 脚本 | 说明 |
|---|---|---|
| 1 渲染输入 | `tools/run_eval.py` | 读取题目和 meta，按条件渲染；输入哈希相同的请求直接读缓存 |
| 2 调用模型 | `tools/run_eval.py` | 并发调用，失败自动重试；原始回复全部落盘 |
| 3 打分 | `tools/score.py` | 按第 5、6 节计算，输出 `scores.json` 和 `report.md` |
| 4 错误分析 | 人工 | 每个模型抽 20 个错例，按下列类别归因：没找到历史关联、过度归因、线索选错、证据定位错、标签理解错、格式错误 |

**预算估算：** full_history 每题约 1–2 万输入 token，63 题 × 2 种选项顺序约 200 万；evidence_only 每题只有几千 token，x_only 更少。合计每个模型约 250 万输入 token；输出很短，可以忽略。

## 10. 已知局限

- **题量小。** 63 题只够做 pilot，指标只用于检验题目和流程，不用于下结论。
- **单一来源。** 目前全部来自 LoCoMo，且历史是英文。
- **图片只有文字描述。** LoCoMo 的 BLIP 描述有错（例如 conv-42 S24 把毛绒玩具狗描述成猫）。以后可以加一个“多模态模型直接看原图”的条件作为对照。
- **出题和探针用的模型可能和被测模型同源。** 报告里要注明哪些模型参与过出题或校验。
- **情绪标签不统一。** 你早先的 pilot 文件（eval.json 示例）用了 `warmth_and_appreciation`、`mixed` 这类自由描述，需要先映射到第 4.3 节的枚举，或在情绪指标中排除。

---

## 11. Pilot 的通过标准

pilot 跑完后，满足以下条件再扩大数据规模：

| 条件 | 门槛 |
|---|---|
| x_only 的 T1 macro-F1 | ≤ 0.5 |
| 最强模型的 Δ(full − x_only) | ≥ 0.15 |
| evidence_only ≥ full_history | 对多数模型成立 |
| 误归因率 | 不同模型之间有可区分的差异（置信区间不完全重叠） |
| 人类基线 | 准确率 ≥ 0.8，κ ≥ 0.6 |

未达到时，对照第 8 节定位是哪类题出了问题，修改出题规则后重新生成。
